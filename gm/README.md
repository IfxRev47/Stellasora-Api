# 本地 GM（Vue3 + Node）

直连 `server/Stella.LocalGateway/Data/stella.sqlite` 的本地管理台：账号、存档、资源、引导进度、大厅展示都在浏览器里改，不走游戏协议，不需要登录游戏。

## 启动

```bash
cd gm
npm install
npm run dev          # API :8787 + Vite :5180，浏览器打开 http://127.0.0.1:5180
```

生产模式（单进程，API 直接托管打包产物）：

```bash
npm run build
npm start            # http://127.0.0.1:8787
```

前置条件：数据库必须已经由本地网关建好（`user_version != 0`）。第一次打开 GM 时会自动执行网关同款 v1 → v2 迁移，补 `created_at` / `updated_at` 两列。

## 能做什么

底部常驻六类功能导航：**账号管理、角色存档、邮件发奖、物品目录、注册管理、公告管理**。账号页管理资料、建角与密码；存档页管理资源、引导与大厅展示；邮件页选择左侧账号后发奖。切换分类时保留选中账号，URL 的 `?tab=` 可直接打开对应分类。

| 区域 | 能力 |
| --- | --- |
| 账号列表 | 搜索 UID / 账号，展示昵称、等级、是否测试号、是否已建角 |
| 新建账号 | 账号 + 密码（PBKDF2-SHA256 / 210000 轮，和网关同格式），可选同时按模板建角色 |
| 角色资料 | 昵称、签名、性别、头像 ID；校验规则与网关 `1004` 一致（1-14 字、≤21 字节、不以数字开头） |
| 资源 | `PlayerInfo.Res` 的 Tid / Qty 增删改，保存时整体替换 |
| 引导进度 | `Acc.Newbies` 的 GroupId / StepId，一键把 1-3 组置为 `-1` |
| 大厅展示 | `PlayerInfo.Board` 的展示 ID，最多 8 个 |
| 角色存档 | 未建角的账号可直接补建；也可删除存档重测建角 |
| 账号操作 | 重置密码；删除账号（预置测试账号 UID 10001 不允许删除） |
| 物品查询 | 按 ID / 中文名查询客户端物品目录，显示类型、说明及是否支持发放 |
| 邮件下发 | 给选中角色发送标题、正文、发件人、有效天数和附件；查看已读/已领取/置顶状态 |
| 注册码 | 批量生成、使用次数、有效期、备注、停用/启用及兑换账号记录 |
| 玩家注册 | `/register` 注册页，确认密码；可选择开放注册或必填注册码；仅建账号不建角色 |
| 公告管理 | 分类、标题、纯文本正文、排序、定时发布/到期、草稿、删除与正文预览；网关即时读取已保存内容 |

公告写入共享 `game_notices` 表。两条常驻系统/活动公告保证客户端至少有两个非空分类，只能改标题、正文和排序；自建公告可下架、定时和删除。列表与正文由网关按客户端格式加密，GM 预览显示转义后的纯文本。游戏关闭后重新打开公告面板获取更新，暂不发送公告变化通知。

管理员“新建账号”允许不填注册码；如果填入则校验并扣除使用次数。玩家注册页与网关 `/account-api/register` 共用同一注册策略和注册码表，单次码被两个进程并发使用时只允许一个建号成功，失败不会留下半成品账号。网关注册请求使用 `registrationCode` 字段。

重置密码会递增 `account_security.password_revision`，使网关的测试账号运行时密码覆盖让位于数据库新密码。前端显示处理中/成功/失败，失败保留输入。请退出游戏的自动登录后再输入新密码验证，新版 SDK 长期票据会因密码版本变化失效；已认证游戏会话暂不主动踢下线。

邮件使用共享 `game_mail` 表，游戏端已接入 9001/9004/9007/9010/9013。附件只支持资源和普通背包道具，领取时状态与入账同事务提交并返回增量 ChangeInfo，重复或并发领取不会重复发奖。发信后重新打开游戏邮箱刷新，暂未接入邮件红点通知。

个人页展示皮肤可在资料区修改，必须已拥有；旧存档缺失 SkinId 时，GM 与网关读取时自动补有效皮肤，避免客户端个人信息页查皮肤配置报错。

存档以 protobuf 存库，后端用 `protobufjs` 加载 `server/Stella.LocalGateway/Protocol/player_data.proto` 解码/编码，只改目标字段，其余字段原样写回。

## 配置

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `GM_DB` | `../server/Stella.LocalGateway/Data/stella.sqlite` | 要操作的库；可指向副本做演练 |
| `GM_PORT` | `8787` | API 端口 |
| `GM_HOST` | `127.0.0.1` | 只监听回环，不要改成 `0.0.0.0` |
| `GM_PROTO_DIR` | `../server/Stella.LocalGateway/Protocol` | proto 目录 |
| `GM_SEED_DIR` | `../server/Stella.LocalGateway/Fixtures/test` | 新角色模板 |

## 安全与并发

- 服务只绑 `127.0.0.1`，**没有任何登录鉴权**，不要把端口暴露到局域网或公网。
- 所有写操作走 `BEGIN IMMEDIATE` + `busy_timeout=5000`，遇 `SQLITE_BUSY` 重试 6 次；和运行中的网关可以同时写，但不要跑两个 GM 实例做同一笔修改。
- 删除账号、删除存档不可恢复；预置测试账号有服务端拦截。
- 日志不打印密码；数据库里只有盐和哈希。

## 已验证

- 在库副本上跑过：建号（含/不含角色）、重复账号 409、非法输入 400、改名、资源、展示、引导、重置密码、删档、删号。
- 反向验证：GM 改名与改资源后，用网关 `GET /_dev/player-fixture` 读到的是新值；GM 创建的账号能在 `/account-api/login` 用新密码登录并返回 `hasCharacter=true`。
- 本批独立测试库运行 Probe `gm` 模式通过 35 项端到端检查，覆盖新旧密码、个人资料、中文物品查询、邮件并发领取、GM 与网关并发兑换单次码。`npm run build` 与 .NET 编译通过。
- 公告验证：先从仓库根执行 `dotnet build server/Stella.LocalGateway -o work/notice-check -p:UseAppHost=false`，再运行 `npm run test:notices`。该脚本用临时库验证 GM 发布到客户端加密列表/正文的完整链路，不修改现有玩家库。

## 已知限制

- `node:sqlite` 在 Node 22 仍是实验特性，启动时会有 `ExperimentalWarning`，功能正常。
- 改完存档需要客户端重新登录才看得到；GM 不发服务器通知。
- 角色等级、装备、任务等字段目前只读展示（走“原始存档”查看）；角色、装备、皮肤类附件尚不支持发放。
- 注册码支持批量生成与兑换记录；尚无全局审计日志或存档导入导出。管理台仍只供本机使用，没有管理员登录鉴权。
